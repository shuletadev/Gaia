# AZ-900: Azure Fundamentals labs

Source: [MicrosoftLearning/AZ-900-Microsoft-Azure-Fundamentals](https://github.com/MicrosoftLearning/AZ-900-Microsoft-Azure-Fundamentals),
`Instructions/Labs/` (updated 2026-08-13). Each lab says it needs "an Azure subscription with sufficient permissions" and
ends with a clean-up step. Read: all five lab files (labs 02 and 03 in full for their first tasks, 05, 06 and 08 for resources and
settings). Learn side: none of the six Azure Fundamentals modules I checked (core architecture, compute, storage, identity,
cost management, governance) has an exercise unit.

| Lab | What students create | Prescribed settings | For guardrails |
|---|---|---|---|
| 02 Create an Azure resource (about 15 min) | Resource group `IntroAzureRG`, then a VM `my-vm` | Region: any available; size left at default; password auth, user `azureuser`; **public inbound ports: None**. Result: a VM plus its NIC, disk, VNet and (probably) an NSG | VM resource types; default size is a D-series; student must be able to delete the group at the end |
| 03 VM as a web host (about 20 min) | Same group name, a Linux VM `my-vm`, then **Cloud Shell** commands | Region where D-series Linux sizes exist; default size; public inbound ports left at default; `az vm extension set` runs a **Custom Script Extension** that downloads a script from `raw.githubusercontent.com` and installs nginx; a later task opens port 80 with a network security group rule | VM extensions and outbound internet to GitHub; NSG rule changes; Cloud Shell storage; a public IP per student |
| 05 Create a storage blob | Storage account (new group `IntroAzureRG`), a container, an uploaded image | Standard performance, **LRS**; Advanced tab: **"Allow enabling anonymous access on individual containers" checked**; container private, then blob access changed | Policies that deny anonymous blob access would **break this lab**; storage account name must be globally unique |
| 06 Pricing calculator | **Nothing in Azure** | Web-based calculator only | None |
| 08 Resource lock | Group `IntroAzureRG` in **Central US**, a storage account (Standard, LRS), then a read-only lock, then a delete lock | Region fixed to **Central US**; the student adds, changes and removes locks and deletes the account | **Needs lock write/delete rights (Contributor lacks them)**; Central US must be allowed |

## Notes

- Every lab names the group `IntroAzureRG`; students in one subscription cannot share it (see the overview).
- Labs 02 and 03 end by deleting the resource group (with "force delete" for VMs). Plan for a re-provision button.
- The VM labs create real compute (a D-series VM costs on the order of $0.1/hour), so expiry and a budget matter more
  than anything else here. Student VMs left running overnight are the main cost risk.
- Allowed resource types for this course (draft, from the labs): resource groups, virtual machines, disks, network
  interfaces, public IP addresses, virtual networks, network security groups, VM extensions, storage accounts and blob
  containers, management locks. Regions: Central US plus the course's chosen default.
- Not verified: the exact default VM size and image in the current portal, and whether lab 02's VM creation also adds a
  public IP when inbound ports are "None". Check both in a test subscription before writing the policy.
