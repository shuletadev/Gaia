# DP-900: Azure Data Fundamentals labs

Source: [MicrosoftLearning/DP-900T00A-Azure-Data-Fundamentals](https://github.com/MicrosoftLearning/DP-900T00A-Azure-Data-Fundamentals),
`Instructions/Labs/` (updated 2026-06-22). A mapping file ties them to the course modules, and says instructors may also
assign the exercises in the Learn learning paths. Read: the mapping in full and a keyword extraction of each lab (its
settings, not every step).

| Lab | Course module | What students create | Azure resource group? |
|---|---|---|---|
| 01 Azure SQL Database | Relational data | A SQL server with **SQL authentication**, and a database named **`Dealership`**: compute left unchanged, **locally-redundant backup storage**, no sample data; firewall settings opened so the student can connect; tables created by the student | Yes |
| 02 Azure Storage | Non-relational data | A storage account (Standard, LRS), then **upgrade it to Data Lake Gen2**, a container `data` (private), a file share `files`; soft delete and backup options turned off | Yes |
| 03 Azure Cosmos DB | Non-relational data | A Cosmos DB account **for NoSQL**, then a Data Explorer quick start (`SampleDB` / `SampleContainer`), items and queries | Yes |
| 04b Microsoft Fabric | Analytics | A **Fabric workspace** with a lakehouse, a copy job from a sample dataset (NYC taxi), a SQL analytics endpoint | **No: tenant-level** |
| 05c Real-time in Fabric | Analytics | An **Eventstream** and **Eventhouse** in a Fabric workspace | **No: tenant-level** |
| 06 Visualize with Power BI | Analytics | Power BI **Desktop** (a local application) | **No** |

## For guardrails

- Resource types for labs 01 to 03 (draft): `Microsoft.Sql/servers` and databases (a small tier only), storage accounts
  (including the Data Lake upgrade), `Microsoft.DocumentDB/databaseAccounts` (NoSQL). Note lab 02's upgrade turns on the
  hierarchical namespace: a policy blocking it breaks the lab.
- Lab 01 needs the SQL server firewall open to the student's address; a policy that forbids firewall rules breaks it.
- Cosmos DB accounts can be created with serverless or the free tier; the free tier is limited to one per subscription, so
  a class would hit it at once. Prefer serverless in the substitution note.
- Fabric (labs 04b and 05c) needs a Fabric license or capacity and tenant settings: none of that is controlled by an Azure
  policy or an Azure budget, and "clean up" means deleting the workspace. Power BI Desktop needs nothing from Azure.

## Effect on the instructor catalog

The current analytics labs teach **Fabric**, while catalog lab 11 uses Synapse. Choose: keep lab 11 as a data-lake demo, or
add a Fabric variant. Fabric capacity can be deployed from a template (`Microsoft.Fabric/capacities`, billed while it runs and
pausable), but workspaces, lakehouses and the tenant settings are not templates. Decide after you know whether the business
tenant has Fabric.
